# Несколько архивов в GameSpace PWA

## Управление

В меню **Мои архивы** находятся встроенное демо и добавленные пользователем
локальные сайты. **Добавить архив** создаёт отдельную запись и делает её
выбранной после успешной проверки. Архивы с одинаковыми именами независимы.
Исходный сжатый файл не сохраняется второй копией: хранятся распакованные файлы.

**Открыть** выбирает запись и запускает её витрину. При следующем запуске PWA
открывается последнее выбранное содержимое. **Переименовать** меняет название
в списке, сохраняя имена файлов внутри. **Заменить** принимает полный архив
взамен только этой записи. Быстрое обновление из блока **Локальные архивы**
применяется только к выбранному архиву, с прежним журналом отката.

**Удалить** требует подтверждения с названием и удаляет только файлы указанной
записи. После удаления выбранной записи меню остаётся открытым; при наличии
других установленных архивов выбирается первая оставшаяся запись. Общие
сохранения игр на этом этапе сохраняются.

Строка встроенного демо всегда находится в списке. Первое открытие готовит его
из автономного пакета оболочки. **Восстановить демо** возвращает встроенные
файлы только в этой записи. **Удалить файлы** освобождает её распакованное
содержимое; строка и возможность повторной подготовки остаются. Свои архивы
не заменяются при подготовке демо.

Раздел **Память приложения** учитывает сумму размеров и числа файлов всех
зарегистрированных архивов. Кнопка **Перепроверить файлы** проверяет выбранную
запись. Все архивы расходуют общую квоту браузера; GameSpace не удаляет
неактивные записи автоматически ради свободного места.

## Сохранения игр: первый этап

Сейчас отдельно хранятся распакованные файлы архивов. `localStorage`,
`sessionStorage`, IndexedDB, cookies, Cache Storage и данные, создаваемые
самими играми через OPFS, не разделяются по архивам. `sessionStorage` ограничен
окном браузера, но не идентификатором архива. При совпадении имён записей
сохранения разных версий игры могут пересекаться. В меню это указано явно.

Настройки оболочки, история браузера и диагностические отчёты остаются общими.
Базовая проверка совместимости относится к текущему содержимому; переход к
другому архиву сбрасывает прежние наблюдения. Номер формы и алгоритм GS1 не
изменены.

Следующий отдельный этап: переключение наборов `localStorage` и настройка
**Единый localStorage**. Разделение остальных API хранения требует отдельного
решения. APK получит управление несколькими архивами после согласования и
проверки PWA.

## Хранилище и неизменяемый runtime v1

Существующий `sw-runtime-v1.js` сохранён побайтно. Версия IndexedDB остаётся 1,
объектное хранилище `app` прежнее. Ключ `archive-catalog-v1` содержит список,
стабильные идентификаторы, названия и метаданные записей. Ключ `state` содержит
совместимую с runtime v1 проекцию выбранного архива. Список и `state` меняются
одной транзакцией; отдельный воркер для списка не нужен.

Новые распакованные версии располагаются в `gamespace/archives/<revision-id>`.
Уже установленный сайт из `gamespace/revisions/` включается в список без
копирования или распаковки: большой архив не требует двойного места для
переноса. Очистка сохраняет все зарегистрированные каталоги обоих корней,
удаляет только незарегистрированные ревизии и временные области.

Runtime v1 отдаёт содержимое одной глобально выбранной записи по прежним URL
`__gamespace_content__/`. Поэтому просмотр разрешён в одном окне PWA:
блокировка `gamespace-content-view-v1` удерживается до уничтожения iframe.
Переключение, импорт, обновление и удаление из другого окна отклоняются с
предложением закрыть просмотр. Закрытие или авария окна освобождают блокировку
средствами браузера. Все файловые операции дополнительно используют прежнюю
блокировку `gamespace-site-operation-v1`.

## Сбои и откат оболочки

Полный импорт готовится в новой ревизии. До проверки всех файлов и успешной
транзакции прежние записи остаются рабочими. Замена удаляет предыдущую ревизию
только указанного архива после фиксации новых метаданных. Сбой после фиксации
может оставить временные файлы: следующая очистка убирает их.

Перед удалением в одной транзакции меняются список, выбранная запись и журнал
`site-delete`. При прерывании удаления журнал повторяется при следующем
запуске. Update-архив использует прежний журнал `update-merge`; список,
метаданные выбранной записи и очистка журнала фиксируются одной транзакцией.

Прежняя оболочка после отката видит только выбранный сайт. Её стартовая очистка
не обходит новый корень `gamespace/archives/`; поле `activeRevision` в проекции
дополнительно сохраняет имя перенесённого старого каталога, а `archiveRevision`
содержит настоящую ревизию выбранной записи. Это позволяет сохранить
неактивный старый сайт при обычном запуске старой оболочки.

Старые версии приложения не умеют управлять списком: полная замена или
удаление в старом меню могут удалить выбранный каталог. Для управления
несколькими архивами вернитесь к новой версии. Одновременный запуск старой и
новой оболочек не поддерживается: старые выпуски не знают блокировку просмотра.
Не обещается полная совместимость управления архивами со старыми оболочками.
