# Android GameSpace Loader APK: описание решения

Документ фиксирует текущее устройство `apk-gamespace`: зачем оно сделано, какие проблемы уже решены, как собирать APK и что важно помнить при будущих доработках.

`apk-gamespace` рассчитан на случаи, когда локальный сайт слишком большой, чтобы класть его внутрь APK.

Прежний подход со встроенным сайтом:

```text
APK -> assets/site/index.html
```

Новый подход:

```text
APK -> маленькое WebView-приложение
ZIP/7z -> выбирается на телефоне
site-files -> распаковывается в каталог приложения
WebView -> file:///.../index.html
```

Главная идея: APK устанавливается один раз, а сайт можно заменять отдельным ZIP/ZIP64 или 7z-архивом без пересборки APK.

## Зачем понадобилось второе решение

У APK есть практические ограничения по размеру. Если сайт содержит много игр, изображений, аудио или видео, полный APK становится слишком большим, долго собирается и может упереться в ограничения Android-инструментов, файловой системы или способа передачи файла.

В `apk-gamespace` сайт хранится отдельно:

1. Пользователь переносит на телефон один ZIP/ZIP64 или 7z-архив.
2. Приложение выбирает архив через системный `ACTION_OPEN_DOCUMENT`.
3. Архив потоково распаковывается в каталог приложения.
4. WebView открывает локальный `index.html`.

Так можно работать с очень большими офлайн-сайтами. Ограничение переносится с размера APK на свободное место телефона и время распаковки.

`build-apk.bat` - основной запуск для пользователя.

`build-apk.ps1` - внутренняя логика сборки через Android SDK tools.

`install-android-sdk.bat` - установка Android command-line tools, если SDK не найден.

`android-webview-loader` - Android-проект приложения-загрузчика.

`MainActivity.java` - вся основная логика UI, выбора архива, распаковки, обновления и WebView.

`icon-source/gamespace-icon-1024.png` - исходник иконки приложения.

`app/src/main/assets/demo.7z` - встроенный демо-сайт для проверки приложения без внешнего архива.

Важно: исходником для встроенного демо считается общий каталог:

```text
demo/
```

При каждой сборке `build-apk.ps1` запускает `tools/build-demo.ps1`, создаёт и
проверяет 7z-архив, а затем сохраняет его в:

```text
apk-gamespace/android-webview-loader/app/src/main/assets/demo.7z
```

Поэтому обновлять нужно файлы непосредственно в `demo/`; копия в assets
является сборочным результатом и не публикуется как исходник.

Неизменённый официальный GameSpace можно устанавливать и использовать вместе
со встроенным демо. Для основной работы можно загрузить собственный архив и
оставить демо доступным в приложении. Извлекать демо-игры и переносить их в
собственный архив, сайт, изменённую сборку или другой проект нельзя; см.
`demo/DEMO_CONTENT_LICENSE.md`.

## Android-параметры

```text
package/applicationId: ru.local.gamespace.loader
app name: GameSpace
minSdkVersion: 23
targetSdkVersion: 36
compileSdkVersion: 36
versionCode: 300 для версии 0.3.0
versionName: 0.3.0
orientation: sensorPortrait
```

APK и PWA используют единый номер выпуска из тега GitHub Release. Допустимы
канонические сокращения `vMAJOR`, `vMAJOR.MINOR` и
`vMAJOR.MINOR.PATCH`: например, `v1`, `v0.5` и `v0.6.22`. Для APK номер
нормализуется до трёх компонентов, а `versionCode` вычисляется по формуле
`MAJOR × 10000 + MINOR × 100 + PATCH`.

Package отличается от старого `ru.local.gamespace`, поэтому `apk-gamespace` может стоять рядом с ранее собранной версией приложения.

`targetSdkVersion 36` нужен для требований Google Play к новым приложениям и обновлениям после 31 августа 2026.

В `AndroidManifest.xml` нет разрешения `INTERNET` и нет storage-разрешений.

## Ориентация

В `AndroidManifest.xml`:

```xml
android:screenOrientation="sensorPortrait"
```

Это фиксирует приложение в портретном режиме, но позволяет переворот на 180 градусов. Горизонтальная ориентация не используется, потому что игры рассчитаны на вертикальный экран.

## Что делает приложение

`MainActivity.java`:

- показывает стартовый экран, если сайт еще не установлен;
- открывает системный выбор файла через `ACTION_OPEN_DOCUMENT`;
- принимает ZIP/ZIP64 через `ContentResolver.openInputStream`;
- принимает 7z через `ParcelFileDescriptor` и `SevenZFile`;
- читает ZIP потоково через `ZipInputStream`;
- читает 7z через seekable `FileChannel`;
- защищается от опасных ZIP-путей;
- распаковывает файлы в app-specific storage;
- ищет `index.html` или `index.htm`;
- сохраняет путь к сайту в `SharedPreferences`;
- открывает index в Android `WebView`;
- умеет быстро или полностью обновлять сайт;
- показывает прогресс длительных операций;
- показывает информацию о версии и последнем обновлении;
- очищает установленный сайт по команде пользователя.

## WebView-настройки

В WebView включены:

```text
JavaScript
DOM Storage
Database
File access
Content access
Media playback without required user gesture
Load with overview mode
Wide viewport
File access from file URLs
Universal access from file URLs
```

Локальные URL остаются внутри WebView:

```text
file:
about:
javascript:
```

Внешние URL открываются через обычный Android `Intent`.

Главная страница распознает независимые URL-параметры `app`, `tv` и `author`. `app` и `tv` включают предварительную загрузку изображений всех видимых карточек. `author` удаляет игры с итоговым `creator: "students"`, скрывает опустевшие разделы и пересчитывает общий счетчик. Параметры можно объединять через `&`, например `index.html?tv&author`.

Главный `index.html` постоянно живет в `homeWebView`, а игры и остальные страницы открываются в отдельной `webView`. При возврате на главный экран вторая WebView очищается, а состояние первой сохраняется. Звук и медиаконтент главной страницы при переходе к игре приостанавливаются и восстанавливаются при возврате.

При первом открытии игры вторая WebView загружается с `View.INVISIBLE`, пока главная страница сохраняет на экране последний кадр. После `onPageFinished()` вызывается `postVisualStateCallback()`, и WebView игры становится видимой только из `VisualStateCallback.onComplete()`.

Если подготовка занимает больше 0,5 секунды, поверх главной страницы показывается нативный индикатор. Через 1 секунду появляется текст `Загрузка игры…`, через 10 секунд - `Загрузка занимает больше времени…`. Оверлей сразу блокирует повторные нажатия, даже пока еще полностью прозрачен.

Кнопка Android `Back` сначала отменяет ожидающую загрузку игры либо идет назад внутри видимой WebView. Если истории нет, закрывает Activity обычным способом. Во время распаковки `Back` не прерывает операцию и показывает просьбу дождаться завершения.

## Верхняя панель приложения

Панель находится поверх WebView, а не занимает высоту страницы. Поэтому при скрытии панели сайт не перестраивается.

Параметры:

```text
фон: 50% прозрачности
автоскрытие: 5 секунд
шаг полосы обратного отсчета: 50 мс
```

Кнопки:

```text
←  Назад внутри сайта
⌂  Главное меню / текущий index.html
⚙  Настройки приложения
```

Поведение:

- при установленном сайте панель показывается на 5 секунд и скрывается;
- тонкая полоска под панелью показывает оставшееся время;
- при возврате приложения на экран после переключения панель снова показывается на 5 секунд;
- тап по верхнему краю сайта не открывает панель, чтобы не мешать игровым кнопкам;
- пока открыт диалог приложения, таймер скрытия остановлен;
- после закрытия диалога таймер снова запускается с 5 секунд.

Это реализовано через `topBarHoldCount`, `showHeldDialog(...)`, `startTopBarCountdown()` и `shouldAutoHideTopBar()`.

```text

```

Если сайт установлен:

```text

```

`Выбрать архив` и оба режима обновления используют один и тот же Android file picker. После выбора URI приложение пытается взять persistable read permission, но не зависит от него для немедленной распаковки.

Для ZIP достаточно потокового чтения. Для 7z нужен случайный доступ к файлу архива, поэтому обычные файлы из локальной памяти телефона подходят, а некоторые облачные/виртуальные провайдеры могут вернуть ошибку seekable-доступа.

## Встроенный демо-сайт

Для модерации и быстрой проверки в APK встроен маленький архив:

```text
apk-gamespace/android-webview-loader/app/src/main/assets/demo.7z
```

Этот файл не хранится как исходный. Перед сборкой он автоматически создаётся из
непосредственного содержимого общего каталога `demo/` скриптом
`tools/build-demo.ps1`.

Если сайт еще не установлен, на стартовом экране показываются две кнопки:

```text
Выбрать архив
Загрузить встроенный демо-сайт
```

Текст стартового экрана:

```text
Сайт не установлен

Выберите ZIP/7z-архив с сайтом или загрузите встроенный демо-сайт для проверки приложения.

Демо-сайт распакуется во внутренний каталог приложения и запустится без интернета. Позже его можно заменить своим архивом через настройки.
```

Встроенный 7z нельзя напрямую передать в `SevenZFile`, потому что asset внутри APK может быть сжат. Поэтому `installBuiltinDemoSite()` сначала копирует `demo.7z` из assets в cache приложения как `builtin-demo.7z`, а потом распаковывает его через тот же 7z-код, что и пользовательские архивы.

После установки в `Информация` режим последнего обновления отображается как:

```text
встроенное демо
```

## Хранилище для больших сайтов

Приложение выбирает app-specific external storage с максимальным свободным местом:

```text
Android/data/ru.local.gamespace.loader/files/gamespace-loader/site-files
```

Причины:

- Android разрешает приложению писать в свой app-specific каталог без storage-разрешений;
- это обычно большая общая память телефона;
- `getExternalFilesDirs(null)` может вернуть несколько вариантов, включая SD-карту;
- приложение выбирает вариант с максимальным `usableSpace`.

Если external storage недоступен, используется внутренний app-specific каталог.

Если сайт уже установлен, приложение предпочитает ранее сохраненный базовый каталог. Это важно, чтобы обновление не переехало на другое хранилище неожиданно для пользователя.

При удалении приложения Android удалит его app-specific каталог вместе с распакованным сайтом. При обновлении APK поверх старого приложения данные должны сохраниться.

## Рекомендации для создания архива

В 7-Zip выбирать:

```text
Формат архива: zip
Путь к файлам: Относительные пути
Создать SFX-архив: выключено
Разбить на тома: пусто
Шифрование: не использовать
```

Для самой быстрой подготовки и распаковки больших сайтов:

```bat
"C:\Program Files\7-Zip\7z.exe" a -tzip -mx=0 site.zip site
```

Для меньшего размера при умеренной скорости:

```bat
"C:\Program Files\7-Zip\7z.exe" a -tzip -mm=Deflate -mx=3 site.zip site
```

ZIP64 7-Zip включает автоматически, когда это нужно. Приложению нужен один цельный ZIP-файл, без разбиения на тома.

В GUI 7-Zip для ZIP можно указать UTF-8 имена в поле `Параметры`:

```text
cu=on
```

Это GUI-аналог командного `-mcu=on`.

Вариант 7z:

```bat
"C:\Program Files\7-Zip\7z.exe" a -t7z -mx=0 site.7z site
```

7z хранит имена файлов в Unicode и лучше переносит кириллицу в путях. В приложении 7z распаковывается через Apache Commons Compress + XZ for Java. Ограничения: нужен один цельный архив, без шифрования и без многотомности; провайдер Android должен дать seekable file descriptor.

Для быстрого обновления важны даты файлов в архиве. Если дата записи в архиве не новее локального файла, файл будет пропущен. Если у записи архива нет нормальной даты, файл распаковывается заново.

## Полное обновление

Полное обновление используется при первой установке и при выборе `Полное обновление из архива`.

Логика:

1. Выбрать базовый каталог хранения.
2. Удалить старый `site-files`.
3. Создать `site-files`.
4. Прочитать архив выбранным распаковщиком.
5. Распаковать все допустимые файлы.
6. Найти `index.html` или `index.htm`.
7. Сохранить сведения в `SharedPreferences`.
8. Открыть сайт в WebView.

Если полная распаковка срывается, приложение удаляет неполный каталог, показывает ошибку и возвращается на экран выбора архива.

Полное обновление нужно, когда важно удалить файлы, которых больше нет в новом архиве.

## Быстрое обновление

Быстрое обновление используется только когда уже есть установленный сайт.

Логика:

1. Старый каталог не удаляется.
2. Приложение читает только выбранный архив.
3. Для каждой файловой записи архива вычисляется безопасный путь назначения.
4. Если файла на телефоне нет, файл записывается.
5. Если файл есть и запись архива новее локального файла, файл перезаписывается.
6. Если файл есть и не старее записи архива, файл пропускается.
7. Файлы, которых нет в архиве, остаются на телефоне.

Отдельного этапа поиска устаревших файлов нет. Это намеренно: для сайтов на десятки гигабайт обход всего установленного каталога может быть дольше самого полезного обновления.

В информации после быстрого обновления показывается:

```text
Новых/обновленных загружено
Пропущено файлов
Записано данных
Общее время
Время распаковки
```

Если быстрое обновление срывается, приложение оставляет старый сайт и заново открывает предыдущий `index.html`.

## Диагностика ошибок архива

При ошибке распаковки приложение теперь показывает не только короткий Toast, а подробное окно с диагностикой:

```text
Этап
Архив
Режим
Размер архива
Прочитано архива
Записано данных
Записей архива обработано
Файлов записано
Файлов пропущено
Каталог распаковки
Последняя запись архива
Путь назначения
Класс исключения
Сообщение исключения
Подсказки
```

Это сделано для случаев вроде `Malformed[1]`, когда стандартное сообщение Android почти ничего не объясняет.

Важная причина `Malformed[1]`: `ZipInputStream.getNextEntry()` может упасть при декодировании имени следующей записи ZIP. Обычно это не размер архива больше 2 ГБ, а кодировка имени файла или каталога. Например, ZIP содержит кириллицу в старой DOS/Windows-кодировке, а Android пытается читать имя как UTF-8.

Рекомендация для переупаковки:

```bat
"C:\Program Files\7-Zip\7z.exe" a -tzip -mx=0 -mcu=on site.zip site
```

`-mcu=on` просит 7-Zip записывать имена ZIP в UTF-8. Альтернативный грубый способ проверки - временно переименовать файлы и каталоги латиницей, цифрами, дефисом или подчеркиванием.

Также приложение подсказывает проверить:

- выбран именно ZIP/ZIP64 или 7z, не `.rar`, SFX или многотомный архив;
- архив полностью скопирован на телефон;
- архив проходит Test/Проверить в 7-Zip;
- нет путей `../`, абсолютных путей и `C:/...`;
- нет слишком длинных имен или путей;
- хватает свободного места для записи.

## Защита при распаковке

`normalizeZipEntryName(...)` отклоняет:

- пустые пути;
- абсолютные пути;
- `../`;
- Windows drive paths вроде `C:/...`;
- выход за пределы каталога `site-files` после canonical path проверки.

Это защищает от Zip Slip и случайного повреждения файлов вне каталога приложения.

## Сборка APK

Самый простой запуск:

```bat
apk-gamespace\build-apk.bat build
```

Или из папки `apk-gamespace`:

```bat
build-apk.bat build
```

Меню:

```text
1 - Build APK
2 - Clean generated files
```

Команды без меню:

```bat
apk-gamespace\build-apk.bat build
apk-gamespace\build-apk.bat clean
```

Готовый APK:

```text
apk-gamespace/release/GameSpace.apk
```

Внутренняя копия:

```text
apk-gamespace/android-webview-loader/app/build/outputs/apk/debug/app-debug.apk
```

## Как устроена сборка

Сборщик использует прямые Android SDK tools и не добавляет большой `assets/site`: основной пользовательский сайт не входит в APK. В APK добавляется только маленький встроенный `assets/demo.7z`.

Шаги:

1. Проверить обязательные файлы Android-проекта.
2. Обновить `app_name`, `app_version_name`, `app_build_date` в `strings.xml`.
3. Пересоздать и проверить встроенный `demo.7z`.
4. Найти Android SDK.
5. Найти JDK, Android platform и build-tools.
6. `aapt2 compile` компилирует ресурсы.
7. `aapt2 link` создает базовый APK.
8. `javac` компилирует Java-код.
9. `d8` создает `classes.dex`.
10. `classes.dex` добавляется в APK.
11. `zipalign` выравнивает APK.
12. `apksigner` подписывает локальную сборку тестовым ключом, а сборку GitHub
    Release — постоянным релизным ключом из Actions Secrets.
13. APK копируется в `release/GameSpace.apk`.

7-Zip требуется для создания встроенного демо. Основной пользовательский сайт
сборщик в APK не упаковывает.

Для поддержки 7z внутри Android-приложения добавлены локальные JAR-файлы:

```text
apk-gamespace/android-webview-loader/app/libs/commons-compress-1.28.0.jar
apk-gamespace/android-webview-loader/app/libs/commons-codec-1.19.0.jar
apk-gamespace/android-webview-loader/app/libs/commons-io-2.20.0.jar
apk-gamespace/android-webview-loader/app/libs/commons-lang3-3.18.0.jar
apk-gamespace/android-webview-loader/app/libs/xz-1.12.jar
```

`build-apk.ps1` добавляет `app/libs/*.jar` в `javac` classpath и передаёт эти
JAR-файлы в `d8`, чтобы классы попали в `classes.dex`. Commons Codec, Commons
IO и Commons Lang являются обязательными runtime-зависимостями Commons
Compress 1.28.0. XZ for Java 1.12 используется вместо 1.10, чтобы включить
последующие исправления библиотеки при сохранении совместимости API.

Также `build-apk.ps1` добавляет файлы из:

```text
apk-gamespace/android-webview-loader/app/src/main/assets
```

в APK по путям:

```text
assets/...
```

Так в APK попадает встроенный `assets/demo.7z`.

Проверить SDK-параметры:

```bat
%LOCALAPPDATA%\Android\Sdk\build-tools\35.0.0\aapt2.exe dump badging apk-gamespace\release\GameSpace.apk
```

Ожидаемо:

```text

```

Проверить подпись:

```bat

```

Ожидаемо:

```text
Verifies
```

Проверить, что сайт не попал в APK:

```powershell
$apk = "apk-gamespace\release\GameSpace.apk"
Add-Type -AssemblyName System.IO.Compression.FileSystem
$zip = [IO.Compression.ZipFile]::OpenRead((Resolve-Path $apk).Path)
$zip.GetEntry("assets/site/index.html")
$zip.Dispose()
```

Результат должен быть пустым.

## Что уже было решено

### Сайт не помещается в APK

Решение: сайт вынесен во внешний ZIP/ZIP64 или 7z-архив и распаковывается на телефоне в каталог приложения.

### Нужно работать без интернета

Решение: APK не содержит `INTERNET` permission. WebView открывает локальный `file://` index, а сайт должен содержать все нужные ресурсы локально.

### Нужны сайты 40 ГБ+

Решение: приложение не копирует архив внутрь себя. ZIP читается потоково из `ContentResolver.openInputStream`, 7z читается через `ParcelFileDescriptor` и seekable `FileChannel`. Основное ограничение - свободное место под распакованные файлы и способность выбранного файлового провайдера отдать большой архив.

### Не нужны storage-разрешения

Решение: архив выбирается через системный file picker, а распаковка идет в app-specific storage.

### Обновление полного сайта долго удаляет и копирует все заново

Решение: добавлен режим `Быстро обновить из архива`, который обновляет только новые и более свежие файлы из архива.

### Поиск устаревших файлов оказался долгим

Решение: отдельный этап поиска файлов, которых нет в архиве, убран. Быстрое обновление не обходит установленный каталог целиком.

### Верхняя панель занимала место сайта

Решение: панель стала overlay поверх WebView с 50% прозрачностью и автоскрытием через 5 секунд.

### Панель мешала игровым кнопкам сверху

Решение: скрытая панель не возвращается по тапу по верхнему краю. Она возвращается при переходе приложения в активное состояние после переключения.

### Таймер скрытия шел во время диалогов

Решение: все AlertDialog показываются через `showHeldDialog(...)`, который удерживает панель и сбрасывает таймер после закрытия.

### Игры рассчитаны на вертикальный экран

Решение: Activity закреплена как `sensorPortrait`, то есть портрет и перевернутый портрет.

## Ограничения

- Поддерживается ZIP/ZIP64 и 7z.
- Нужен один цельный архив, без многотомности.
- На телефоне должно хватать места под распакованный сайт.
- Быстрое обновление не удаляет старые файлы, которых нет в новом архиве.
- Быстрое обновление опирается на дату файла в архиве.
- Если сайт ссылается на интернет-ресурсы, без интернета они не загрузятся.
- Регистр букв в путях важен.
- Все выпуски APK должны подписываться одним и тем же существующим ключом. Ключ и пароли не публикуются, а Release workflow получает их из GitHub Actions Secrets.
- Код написан без Gradle wrapper, основная проверенная сборка идет через `build-apk.bat`.

## Типовой рабочий цикл

1. Подготовить сайт с `index.html`.
2. Упаковать сайт в ZIP или 7z:

   ```bat
   "C:\Program Files\7-Zip\7z.exe" a -tzip -mx=0 site.zip site
   ```

   или:

   ```bat
   "C:\Program Files\7-Zip\7z.exe" a -t7z -mx=0 site.7z site
   ```

3. Собрать приложение:

   ```bat
   apk-gamespace\build-apk.bat build
   ```

4. Установить:

   ```text
   apk-gamespace\release\GameSpace.apk
   ```

5. Перенести архив на телефон.
6. Открыть приложение и выбрать архив.
7. Для малых исправлений подготовить отдельный архив с изменёнными файлами и
   использовать `Быстро обновить из архива`.
8. Для удаления старых файлов использовать `Полное обновление из архива`.

## Короткая сводка для нового чата

`apk-gamespace` - Android WebView loader для больших офлайн-сайтов. Основной сайт не упаковывается в APK; внутри есть только маленький `assets/demo.7z` для проверки. APK маленький, package `ru.local.gamespace.loader`, target SDK 36, без INTERNET permission. При первом запуске пользователь выбирает ZIP/ZIP64 или 7z либо загружает встроенное демо, приложение распаковывает архив в `Android/data/ru.local.gamespace.loader/files/gamespace-loader/site-files` и открывает найденный `index.html`.

Главный код: `apk-gamespace/android-webview-loader/app/src/main/java/ru/local/gamespace/loader/MainActivity.java`.

Сборка: `apk-gamespace\build-apk.bat build`.

Готовый APK: `apk-gamespace\release\GameSpace.apk`.

Критичные особенности:

- использовать ZIP/ZIP64 или 7z;
- не добавлять сайт внутрь APK;
- update-архив должен содержать только изменённые файлы с теми же логическими
  путями, что и в полном архиве;
- не добавлять INTERNET permission;
- сохранять `sensorPortrait`, потому что игры вертикальные;
- верхняя панель overlay, 50% прозрачность, автоскрытие 5 секунд;
- игру показывать только после `postVisualStateCallback`; при долгой подготовке использовать нативный индикатор 0,5/1/10 секунд;
- сохранять поддержку сочетаний параметров `app`, `tv` и `author` на главной странице;
- быстрый режим читает только выбранный архив и не ищет устаревшие файлы в локальном каталоге;
- полный режим удаляет старый сайт перед распаковкой;
- при двух приложениях рядом package/applicationId должны отличаться.
