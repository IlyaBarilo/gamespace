# Проверка обновлений GameSpace APK

## Текущий сценарий

В меню `Меню → Обновление приложения` показываются установленная версия,
последний опубликованный выпуск, дата, размер и описание. Проверка запускается
только кнопкой пользователя. При старте приложения и обычном открытии окна
сетевого запроса нет.

Если доступна новая версия, кнопка `Открыть официальный выпуск` передаёт Android
HTTPS-адрес страницы релиза GitHub. Скачивание APK и установка выполняются
браузером и системными средствами Android вне GameSpace.

GameSpace:

- не скачивает APK во внутреннее хранилище;
- не передаёт APK системному установщику;
- не запрашивает `REQUEST_INSTALL_PACKAGES`;
- не может выполнять бесшумную установку;
- не управляет разрешением установки из неизвестного источника.

Разрешение `INTERNET` остаётся только для ручного чтения официального каталога
выпусков. Импортированные страницы не получают доступа к клиенту обновлений и
не могут запускать нативную проверку.

## Зафиксированное ограничение установки

В выпуске 0.3.16 после добавления прямого скачивания и запуска установки APK
Google Play Защита на Redmi Note 8 Pro стала блокировать GameSpace сообщением
«Вредоносное приложение заблокировано». Ранее установленный выпуск 0.3.14 такой
блокировки не вызывал. После удаления механизма установки APK новый файл снова
устанавливается на этом устройстве.

Чтобы не вернуть эту проблему, в APK нельзя повторно добавлять:

- разрешение `android.permission.REQUEST_INSTALL_PACKAGES`;
- скачивание APK средствами GameSpace;
- передачу APK через installer intent;
- `FileProvider` или другой провайдер, предназначенный для передачи APK
  системному установщику;
- кнопку установки APK внутри GameSpace.

Проверка обновления может только показать сведения о выпуске и по явному
действию пользователя открыть официальную страницу GitHub в браузере. Если
прямую установку когда-либо потребуется вернуть, её следует рассматривать как
отдельное изменение с обязательной проверкой Play Protect на реальном Android,
а не как расширение существующей кнопки проверки обновлений.

## Каталог выпусков

APK читает каталог по фиксированному адресу:

```text
https://ilyabarilo.github.io/gamespace/apk/updates.json
```

Каталог формируется из стабильных GitHub Releases, проверяется при публикации
и содержит до 100 записей. Для каждого выпуска сохраняются версия, `versionCode`,
дата публикации, описание, минимальный Android, URL официального выпуска и
сведения об APK. URL и порядок версий проверяются строго.

Последний успешно полученный каталог сохраняется локально вместе с датой.
Сетевой или форматный сбой не стирает прежний результат. Переадресации клиента
запрещены, применяется системная проверка HTTPS, размер ответа ограничен 1 МиБ.

## Публикация

Скрипты каталога и GitHub Actions продолжают проверять APK релиза и публиковать
`updates.json`. Эти проверки нужны для достоверности сведений на экране и для
перехода на правильный официальный выпуск, хотя APK больше не скачивается самим
приложением.

`prepare-update-catalog.mjs` формирует каталог из локально проверенного APK.
`restore-update-catalog.mjs` восстанавливает историю из опубликованных выпусков.
Они не меняют пользовательские архивы сайта.

Ограничение каталога в 100 записей относится только к метаданным APK. Оно не
связано с хранением версий PWA на Pages и не удаляет GitHub Releases или assets.

## Проверки

`AppUpdateTest.java` проверяет строгий JSON/UTF-8, версии, URL, порядок выпусков,
minSdk, HTTP-ошибки, запрет переадресаций, сохранение последнего результата и
совместимость с каталогом, который формируют скрипты публикации.

`test-diagnostics.ps1` дополнительно проверяет, что APK:

- не содержит `REQUEST_INSTALL_PACKAGES`, installer intent и файловый провайдер;
- не содержит кода загрузки и установки APK;
- открывает официальный `releaseUrl` через браузер;
- показывает описание выпуска перед кнопкой перехода.

Открытие браузера и дальнейшая установка требуют ручной проверки на Android.
