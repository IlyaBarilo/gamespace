# Отчёт базовой проверки совместимости GameSpace

Согласованные требования от 11.09.2026. Документ описывает будущую функцию APK
и PWA; её интерфейс и сбор результатов пока не реализованы.

## Назначение и границы проверки

Участник формирует технический отчёт для автора GameSpace, исследований и
таблицы совместимости GitHub. Формат одинаков для APK и PWA, сбор сведений
реализуется отдельно средствами каждой платформы.

Базовая проверка состоит из четырёх автоматически фиксируемых шагов:

1. Запуск установленного приложения. Для PWA запуск вкладки браузера и запуск
   установленного приложения различаются в отчёте.
2. Успешный импорт архива: распаковка, проверка содержимого и принятие
   установленного сайта приложением завершены.
3. Успешная загрузка HTML-витрины игр.
4. Зафиксированный переход из витрины на внутреннюю страницу игры в оболочке
   GameSpace. Внешняя ссылка или открытие меню таким переходом не считаются.

Наблюдение за взаимодействиями внутри игры, изменение кода игр и ручное
подтверждение работоспособности не требуются. Итог означает прохождение этих
четырёх шагов, а не испытание всех функций игр или предельного размера архива.

Основной контрольный материал — встроенный демо-архив. Его выпуск определяется
версией GameSpace; отдельный номер демо в отчёт не добавляется. Допускается
проверка пользовательского архива с соответствующей отметкой источника.
Проверка не должна автоматически заменять установленный сайт демо-архивом.

Результаты относятся к одной проверке и конкретному установленному содержимому,
версии приложения и среде запуска. Результаты разных импортов не смешиваются.
Изменение приложения, среды или содержимого требует новой проверки; ранее
выполненные, но не наблюдавшиеся программой действия не выдаются за проверенные.

## Окно проверки

Пункт меню: «Проверка совместимости». Окно показывает четыре шага, их состояния,
подсказки по оставшимся действиям и сформированный отчёт.

Предусмотрены начало новой проверки, формирование отчёта заново, копирование,
сохранение и отправка. Участник может сформировать неполный отчёт или отчёт
об ошибке. При недоступности системной отправки остаются копирование и сохранение.
Отправка открывает системный выбор приложения и получателя; автоматической
отправки автору, публикации в GitHub и фоновой телеметрии нет.

Редактируемых полей нет, включая модель устройства, версию системы и даты.
Сведения определяет программа. Отчёт представляет собой неизменяемый снимок:
просмотр, копирование, сохранение и отправка используют один текст. Изменение
состояния проверки не меняет уже показанный отчёт; участник формирует новый.

Постоянное пояснение в окне, вне текста отчёта:

> Отчёт содержит технические сведения об устройстве и результаты проверки.
> Эти сведения будут использованы автором GameSpace для улучшения программы,
> исследований и публикации таблицы совместимости на GitHub. Отчёт не содержит
> имени, контактов, уникальных идентификаторов устройства, содержимого архивов
> и сохранений игр. Отправка добровольна. При отправке через почту или мессенджер
> получатель может видеть ваш профиль или адрес.

Дополнительные пояснения в окне:

> ? — неизвестно; - — не применимо.

> Код помогает проверить, что текст отчёта не повредился при копировании
> или пересылке.

Пояснение о нормализации пробелов и переносов в пользовательском окне не нужно.

## Поля и компактный формат GS1

Каждый раздел занимает одну строку. Пустых строк между разделами нет.
Несколько полей разделяются `; `; имя поля отделяется от значения `: `.
Завершающие точки к строкам автоматически не добавляются. Названия разделов,
полей и их порядок фиксированы для обеих платформ.

Значение, содержащее `;` или двойную кавычку, заключается в двойные кавычки.
Внутренняя двойная кавычка удваивается. Многострочные внешние значения должны
быть безопасно преобразованы в однострочные до формирования снимка и хеша.
Парсер учитывает кавычки и разделяет имя поля и значение по первому двоеточию
за пределами кавычек, сохраняя двоеточия во времени формирования.

- `?` — неизвестно или не удалось определить; один вопросительный знак.
- `-` — неприменимо; обычный ASCII-дефис U+002D.
- Состояния проверки записываются словами, а не символами `?` и `-`.
- Дата и время формирования берутся с устройства, с указанием смещения UTC.
  Это дата создания отчёта, не подтверждённое сервером время испытания.
- Дата установки программы и индивидуальный номер отчёта не включаются.
- `ФОРМАТ: 1` обозначает версию структуры, а не номер отдельного отчёта.
- Назначение отчёта и пояснение о данных остаются только в окне.

Пример структуры с выдуманными данными. Код в этом примере условный, он не
является тестовым вектором для проверки хеша:

```text
GameSpace — базовая проверка совместимости
ФОРМАТ: 1
СФОРМИРОВАН: 11.09.2026 14:32:08 (UTC+03:00)
ПРИЛОЖЕНИЕ: вариант: PWA; версия: 0.4.0; запуск: установленное приложение
УСТРОЙСТВО: производитель: ?; модель: ?
СИСТЕМА: название: ?; версия: ?; базовая ОС: Android; версия базовой ОС: 16
СРЕДА: название: Google Chrome; версия: 150.0.7871.187
ХРАНИЛИЩЕ: режим: постоянное
АРХИВ: источник: демо-архив; формат: 7z; размер: 18,4 МБ; файлов: 126; время импорта: 8 с
ПРОВЕРКА: запуск приложения: успешно; импорт: успешно; загрузка витрины: успешно; переход в игру внутри GameSpace: зафиксирован
ИТОГ: базовая проверка пройдена
Целостность текста: GS1-D4A9C2
```

В APK строка среды содержит фактически используемый WebView и его версию,
а не браузер по умолчанию. На старых Android полные сведения о поставщике
WebView могут быть недоступны. В PWA указывается определённый браузер.

Строка `ХРАНИЛИЩЕ` располагается между средой и архивом. В PWA поле `режим`
получается из фактического результата `navigator.storage.persisted()` при
формировании отчёта: `постоянное` для `true`, `обычное` для `false`, `?` при
недоступности API, ошибке или некорректном результате. Один лишь вызов
`navigator.storage.persist()` не доказывает предоставления постоянного хранения.
В APK браузерный режим хранения неприменим: `ХРАНИЛИЩЕ: режим: -`.
Все варианты участвуют в расчёте целостности текста. Режим описывает состояние
на дату формирования; базовая проверка не подтверждает длительную сохранность.

В разделе PWA «Память приложения» рядом с объёмом показываются текущий режим
и пояснение защиты от автоматической очистки, риска удаления данных и значения
квоты. Постоянное хранение не представляется резервной копией и не защищает от
ручной очистки. Недоступность статуса не блокирует приложение. Исходный архив
рекомендуется хранить отдельно; восстановление из него не возвращает новые
игровые сохранения. Этот интерфейсный пункт реализуется отдельно от будущего
окна отчёта совместимости. Экспорт игровых сохранений требует отдельного этапа
и в текущую доработку статуса хранения не входит.

Название и версия системы производителя учитываются отдельно от базовой ОС.
Пример: `название: Xiaomi HyperOS; версия: 3.0.301.0; базовая ОС: Android;
версия базовой ОС: 16`. Название и версия определяются независимо; знание
производителя устройства не доказывает наличие конкретной системы. Версия
Android не выводится из версии HyperOS или другой системы производителя.
Для iOS/iPadOS указывается сама система и её версия; неприменимые поля
Android-основы обозначаются `-`. Схему для прочих платформ PWA следует проверить
на этапе общего форматирования, сохранив те же имена полей.

PWA не может гарантировать получение модели и точных версий системы и браузера.
Ограниченные или недоступные сведения обозначаются `?`, ручного ввода нет.
Полное определение систем производителей в APK также нельзя гарантировать;
для неподтверждённых значений используется `?`.

Сведения об архиве берутся из завершённого импорта или сохранённого состояния
попытки. Время не округляется до фиктивного нуля для неизвестного результата.
Не требуется перечитывать многогигабайтный архив ради формирования отчёта.
Полные пути, названия пользовательских архивов, URL и названия личного содержимого
не включаются. Число файлов при незавершённом импорте не выдаётся за полный
объём распакованного содержимого.

## Ошибки и незавершённые действия

- `успешно` / `зафиксирован` — наблюдалось соответствующее действие.
- `не выполнено` — действие ещё не совершено.
- `не проверено` — выполнение не проверялось, например из-за ошибки предыдущего шага.
- `ошибка` — программой зафиксирован конкретный сбой.
- `прервано` — сохранено начало операции, завершение не подтверждено после
  прерывания. Само по себе это не устанавливает причину завершения процесса.

После строки `ПРОВЕРКА` при сбое добавляется строка `ОШИБКА` с этапом, кодом
и кратким безопасным описанием. Полный диагностический журнал, стек и личные
пути автоматически не переносятся в отчёт совместимости.

Пример фрагмента:

```text
ПРОВЕРКА: запуск приложения: успешно; импорт: ошибка; загрузка витрины: не проверено; переход в игру внутри GameSpace: не проверено
ОШИБКА: этап: импорт архива; код: QuotaExceededError; описание: превышена квота хранилища браузера
ИТОГ: базовая проверка завершилась ошибкой
ДЕЙСТВИЯ: проверьте доступное хранилище в GameSpace и повторите импорт после освобождения места
```

Если ошибка не возникла, но шаги не завершены, итог — «базовая проверка не
завершена», затем строка `ДЕЙСТВИЯ` с подсказкой. При полном успехе строки
`ОШИБКА` и `ДЕЙСТВИЯ` отсутствуют. Квота PWA не называется свободным местом
устройства. Причина ошибки не угадывается по незавершённому шагу.

Если приложение вообще не установилось или не открывается, сформировать
внутренний отчёт невозможно. Такие испытания учитываются отдельно автором.

## Целостность текста GS1

Хеш вычисляется непосредственно по тексту отчёта, не по скрытому JSON.
Заключительная строка `Целостность текста: GS1-XXXXXX` исключается целиком.
Все остальные строки, включая время, неизвестные значения, ошибки и подсказки,
участвуют в расчёте.

Порядок GS1:

1. Взять текст перед заключительной строкой кода.
2. Удалить только согласованный набор пробельных символов: U+0009–U+000D,
   U+0020, U+0085, U+00A0, U+1680, U+2000–U+200A, U+2028–U+2029,
   U+202F, U+205F и U+3000. Одинаковый явный набор используется в Java,
   JavaScript и инструменте проверки, без зависимости от различий `\s`.
3. Остальные символы и их порядок сохранить. Не изменять регистр, цифры,
   пунктуацию, варианты дефисов и Unicode-нормализацию.
4. Вычислить SHA-256 от UTF-8 полученного текста.
5. Взять шесть средних символов шестнадцатеричной записи SHA-256: позиции
   30–35 при нумерации с единицы (`hex.slice(29, 35)`), вывести в верхнем регистре.

Код помогает обнаруживать изменение текста и простую подмену. Он не доказывает
истинность сведений и не является электронной подписью. Открытый исходный код
позволяет намеренно пересчитать его; защита от такого противника не требуется.
Сервер, секретный ключ, аттестация устройства и отправка данных для вычисления
кода в согласованный объём не входят.

Инструмент автора принимает присланный текст или файл, проверяет целостность
без зависимости от расположения пробелов и переносов, затем разбирает поля.
Неполный текст, несколько строк кода, неизвестный формат и несовпадение кода
дают понятный результат проверки. Дополнительный текст сообщения вне отчёта
не должен незаметно приниматься за часть проверенного отчёта.

## Использование в таблице и исследованиях

Строки таблицы различают APK/PWA, версию приложения, устройство, систему,
браузер/WebView, размер и источник архива. Значение «Базовая проверка пройдена»
сопровождается общей методикой четырёх шагов. Автор проверяет результат перед
публикацией; автоматического изменения таблицы приложением нет.

Отчёт с неизвестной моделью не является подтверждением конкретной модели.
Несколько отчётов могут относиться к одному устройству: число отчётов не равно
числу устройств. Для исследования скорости и больших архивов нужна отдельная
методика; базовые отчёты сами по себе таких выводов не подтверждают.

## Этапы разработки и отдельные коммиты

0. Исправить текущий сбой проверки GitHub Actions. Зафиксировать этот документ
   как согласованный план, не добавляя интерфейс отчёта в исправление CI.
1. Реализовать общий контракт и проверяемые эталонные примеры GS1: успешный,
   неполный отчёт, сбой, неизвестные значения, кавычки, разделители и пробелы.
   Согласовать одинаковое форматирование APK/PWA без объединения их сборок.
2. APK: локальное состояние четырёх шагов, определение доступной среды, окно,
   неизменяемый текст, сохранение, копирование и системная отправка.
3. PWA: тот же сценарий, учёт режима запуска, браузерных ограничений, безопасное
   сохранение состояния и доступные способы экспорта. Игровой код не меняется.
4. Инструмент проверки и разбора полученных отчётов, документация приёма
   результатов для таблицы и проверка полного сценария на целевых устройствах.

После каждого этапа выполняются соответствующие проверки и выдаются точные
команды Git для отдельного коммита пользователя. Сам агент операции Git
не выполняет. Реализация следующего этапа не смешивается с незавершённым
пользовательским коммитом предыдущего этапа.
