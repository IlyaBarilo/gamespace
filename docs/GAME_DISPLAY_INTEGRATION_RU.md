# Режим отображения игр в витрине GameSpace

Этот документ описывает реализованный контракт между витриной `index.html` и оболочками GameSpace PWA и APK. Его можно передать разработчику другого проекта для добавления совместимой витрины.

## Задача

Позволить автору витрины задавать режим отображения отдельной игры, не меняя HTML самой игры:

| Поле в записи игры | Поведение |
| --- | --- |
| `display: "auto"` | Игра занимает всю доступную область витрины. |
| `display: "portrait"` | Оболочка дополнительно ограничивает ширину игры до соотношения 10:16, если доступная область шире. |
| Поле отсутствует или значение неизвестно | Используется `auto`. |

Режим указывается снаружи игры — в её записи массива `games`. Игра, которая уже самостоятельно добавляет поля и адаптируется к экрану, может оставаться в `auto`.

## 1. Добавить поле в запись игры

Пример фрагмента внутри `<script>` в `index.html`:

```js
const games = [
    {
        title: "Первая игра",
        link: "games/first/game.html",

        // display: "auto" — вся доступная область витрины.
        // Если поле отсутствует, также используется auto.
        // display: "portrait" — ограничить ширину до 10:16,
        // если доступная область шире. Высота сохраняется.
        // Режим применяется и ко всем кнопкам сложности этой игры.
        display: "auto",

        difficulties: {
            1: { text: "Легко", link: "games/first/game.html?diff=1" },
            2: { text: "Сложно", link: "games/first/game.html?diff=2" }
        }
    },
    {
        title: "Вторая игра",
        link: "games/second/game.html"
        // display не указан — используется auto.
    }
];
```

При первоначальном подключении у первой игры явно указать `display: "auto"` и оставить поясняющие комментарии. У остальных игр поле не добавлять: все игры продолжат запускаться в авто.

Чтобы позднее включить ограничение для конкретной игры, заменить или добавить в её записи:

```js
display: "portrait",
```

Названия и регистр значений должны быть именно `auto` и `portrait`. Значения `vertical`, `10:16` и `10x16` этим контрактом не предусмотрены.

## 2. Добавить функцию формирования ссылки

Разместить функцию до кода создания карточек и кнопок:

```js
const withGameDisplay = (link, display) => {
    if (!link) return link;

    const url = new URL(link, window.location.href);

    // Параметр предназначен для игр того же источника, что и витрина.
    // Внешние ссылки оставляем без изменений.
    if (url.origin !== window.location.origin) return link;

    url.searchParams.set(
        "gamespaceDisplay",
        display === "portrait" ? "portrait" : "auto"
    );

    return url.href;
};
```

Функция сохраняет остальные параметры ссылки и её фрагмент после `#`. Если `gamespaceDisplay` уже присутствует, значение заменяется режимом из записи игры. Для игр своего источника параметр передаётся явно и при `auto`.

Пример результата для режима `portrait`:

```text
games/example.html?diff=2#play
→ games/example.html?diff=2&gamespaceDisplay=portrait#play
```

Функция возвращает абсолютный URL; выше для краткости показана только относительная часть.

## 3. Использовать функцию во всех вариантах запуска

### Нажатие карточки

Заменить прямое присваивание `game.link`:

```js
window.location.href = withGameDisplay(game.link, game.display);
```

Если перед переходом сохраняются прокрутка, фильтры или состояние витрины, сохранить этот существующий вызов перед навигацией.

### Запуск с клавиатуры

В существующем обработчике карточки использовать ту же функцию. Пример для карточки-контейнера с `role="link"` и `tabindex="0"`:

```js
card.addEventListener("keydown", (event) => {
    // Не перехватываем клавиатуру вложенной ссылки или кнопки сложности.
    if (event.target !== card) return;
    if (event.key !== "Enter" && event.key !== " ") return;
    if (!game.link) return;

    event.preventDefault();
    window.location.href = withGameDisplay(game.link, game.display);
});
```

Для обычной карточки-ссылки `<a>` достаточно сформировать её `href`; Enter обрабатывает браузер.

### Карточка-ссылка

```js
cardLink.href = withGameDisplay(game.link, game.display);
```

### Кнопки сложности

Использовать режим родительской записи игры, даже если у сложности другой HTML-файл:

```js
button.href = withGameDisplay(difficulty.link, game.display);
```

Не брать режим из `difficulty.display`: в этом контракте один `display` записи игры действует на все её варианты запуска.

### Совместимость с существующим `ui=mobile` / `ui=tv`

Если витрина уже содержит функцию `withGameUiMode`, сохранить её:

```js
window.location.href = withGameUiMode(
    withGameDisplay(game.link, game.display)
);

button.href = withGameUiMode(
    withGameDisplay(difficulty.link, game.display)
);
```

`withGameUiMode` здесь — существующая функция проекта, а не новая обязательная зависимость. Если её нет, использовать только `withGameDisplay`. Обработка `ui` должна сохранять остальные параметры URL, включая `gamespaceDisplay`.

## 4. Прямые ссылки без массива игр

Для статической HTML-витрины можно сразу записать параметр в `href`:

```html
<a href="games/example.html?gamespaceDisplay=portrait">
    Запустить вертикальную игру
</a>

<a href="games/example.html?diff=2&amp;gamespaceDisplay=portrait">
    Запустить вертикальную игру — сложность 2
</a>

<a href="games/example.html?gamespaceDisplay=auto">
    Запустить во всю область витрины
</a>
```

В HTML между параметрами используется `&amp;`, а в строках JavaScript — `&`.

## 5. Что делает приложение

Поддержка параметра реализована в GameSpace APK и PWA. Витрина передаёт параметр адреса; размеры окна задаёт оболочка.

1. Настройка соотношения сторон в меню приложения определяет базовую область витрины.
2. Для игры с `gamespaceDisplay=auto` или без параметра используется вся базовая область.
3. Для `gamespaceDisplay=portrait` ширина дополнительно ограничивается:

   ```text
   ширина игры = min(ширина базовой области, высота базовой области × 10 / 16)
   высота игры = высота базовой области
   ```

4. Игра располагается по центру. Свободное место по бокам заполняется чёрным фоном оболочки.
5. При повороте устройства или изменении размера окна расчёт повторяется.
6. При возврате в витрину восстанавливается базовая область. Для входной страницы витрины параметр игнорируется.
7. Режим игры не изменяет сохранённую настройку соотношения сторон в меню.

Например, при базовой области 1920×1080 режим `portrait` даёт окно 675×1080. При области 390×844 ширина остаётся 390: более узкое окно не расширяется.

«Во всю область» означает пространство, доступное витрине с учётом настройки приложения. Это не запрос браузерного Fullscreen API и не принудительный поворот устройства.

## 6. Границы применения

- Сам по себе параметр URL не меняет размеры страницы в обычном браузере или сторонней оболочке без поддержки этого контракта.
- Если другой проект создаёт только витрину для запуска внутри GameSpace, достаточно изменений витрины, описанных выше.
- Если другой проект создаёт собственный контейнер игр, в нём также нужно реализовать чтение параметра и ограничение области по правилам раздела 5.
- Режим определяется адресом текущей страницы. Если многостраничная игра переходит на другую HTML-страницу без параметра, следующая страница использует `auto`. Для сохранения вертикального режима параметр нужно передавать и при таких переходах.
- Не требуется добавлять метатеги в игры, создавать поля внутри HTML игры или менять формат архива.
- Новая витрина попадёт в уже установленный архив GameSpace только после обновления его содержимого. Изменения исходного `index.html` сами по себе не обновляют импортированную копию.

## 7. Проверка после подключения

- У первой игры явно стоит `display: "auto"` с комментариями; у остальных поле отсутствует.
- Нажатие карточки, Enter и кнопки сложности передают один и тот же режим записи игры.
- Сохраняются `diff`, `ui`, остальные параметры и фрагмент адреса.
- На временной тестовой записи с `display: "portrait"` окно ограничивается до 10:16 на широком экране и занимает всю ширину на узком.
- После выхода из вертикальной игры возвращается базовая область витрины.
- Следующая игра без `display` занимает всю базовую область.
- После проверки временное `portrait` убрано, если все игры должны оставаться в авто.
