# FPS отрисовки в GameSpace

В меню PWA и APK есть переключатель **Показывать FPS отрисовки**. По умолчанию он выключен; настройка сохраняется для приложения и не зависит от выбранного архива. В PWA она не входит в переключаемые наборы игровых сохранений localStorage.

При включении в левом верхнем углу витрины или игры появляется небольшой полупрозрачный индикатор. Он не перехватывает касания, клики и управление игрой. На странице без поддерживаемой поверхности отображается **FPS недоступен**.

## Что показывается

- Текущий FPS: обновления основного Canvas за последнюю секунду.
- Минимум и максимум: наименьший и наибольший FPS на пяти секундных отрезках внутри последних 5 секунд.
- Средний: количество обновлений за последние 5 секунд, делённое на 5. В первые 5 секунд используется уже доступное время; ожидания полного окна нет. Неполный секундный отрезок минимума и максимума тоже нормируется по фактической длительности.

Пауза снижает среднее. После секунды без новых кадров текущий показатель и минимум равны нулю. При возвращении из фона статистика накапливается заново. Переход на другую страницу начинает новый замер. Значения за короткие окна могут отличаться на один кадр из-за границ интервала.

Минимум по секундным отрезкам сглаживает отдельные короткие задержки. Он не заменяет длительность худшего кадра или измерение задержки управления.

## Подключение без изменения игр

После загрузки локального HTML оболочка временно оборачивает методы рисования Canvas2D, WebGL и WebGL 2. Уже созданный контекст определяется на следующем вызове рисования. Содержимое HTML, JavaScript и файлов архива не переписывается; распаковка и форматы архивов не меняются. В PWA сохранён неизменяемый `sw-runtime-v1.js`.

Несколько операций рисования в одном браузерном кадре считаются одним обновлением. Настройка влияет только на локальное содержимое. При выключении наблюдатель останавливается, индикатор удаляется и исходные методы API восстанавливаются. Если после подключения другой код заменил тот же метод, его замена не перезаписывается.

PWA использует `pwa-gamespace/src/canvas-fps-runtime.js`; APK содержит идентичную копию в `app/src/main/assets/canvas-fps-runtime.js`. Автоматическая проверка сравнивает их байты. У каждого приложения остаётся собственная сборка; новая общая сборочная зависимость не вводится. Код APK подключается через существующий `evaluateJavascript`, без JavaScript-интерфейса Android и новых разрешений.

## Границы измерения

Это оценка частоты команд отрисовки, а не подтверждение показа каждого кадра дисплеем или завершения работы GPU. Повторное рисование одинаковой картинки считается обновлением. Если логика игры меняется 30 раз в секунду, но Canvas перерисовывается 60 раз, показатель может быть 60.

Выбирается крупнейший видимый Canvas. Маленькая анимированная панель не заменяет большую неопределённую поверхность. Скрытые и отсоединённые элементы не выбираются. Однако перекрытие Canvas другой HTML-панелью не распознаётся полностью; при нескольких крупных поверхностях выбор может быть неоднозначным.

DOM/CSS-анимации, отрисовка в worker/OffscreenCanvas и методы рисования, сохранённые игрой до подключения счётчика, могут быть недоступны. Браузерный цикл не подставляется вместо игрового FPS. Методы, вызываемые до загрузки документа, в начальный замер не входят. Долгая незавершённая загрузка страницы откладывает подключение счётчика.

Изменения состояния Canvas и WebGL-проходы в отдельный framebuffer сами по себе не считаются обновлением видимой поверхности. Ошибочные команды GPU и команды без изменения пикселей отдельно не проверяются. Дополнительные вложенные iframe отдельно не инструментируются. При нативном полноэкранном показе самого элемента Canvas браузер может скрыть HTML-индикатор; полноэкранный показ оболочки или HTML-контейнера его сохраняет.

Измерение добавляет нагрузку. Для обычной игры его можно выключить. Проверка в настольном Chromium не подтверждает производительность телефона, WebView или Safari; эти среды проверяются отдельно на устройствах.
