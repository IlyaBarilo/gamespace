# Контракт формирования отчёта GS1

Этап 1 от 14.09.2026. Форматтеры создают неизменяемую строку по заранее
собранным сведениям. Они не читают данные устройства, не начинают проверку,
не импортируют архив и не открывают сеть. Сбор событий и интерфейс реализованы
отдельными модулями APK и PWA по [плану](./COMPATIBILITY_REPORT_RU.md).

## Реализации и эталоны

- PWA: `pwa-gamespace/src/compatibility-report.js`, функция
  `createCompatibilityReport(input)` возвращает `Promise<string>`.
- APK: `CompatibilityReport.java`, `create(Map<String, ?>)` возвращает `String`.
- Текстовые эталоны: [fixtures/compatibility-report-gs1.json](./fixtures/compatibility-report-gs1.json).
  У каждого примера есть входные значения, точный текст с CRLF, полный SHA-256
  нормализованного тела и шестизначный код. Все сведения вымышлены.

Сборки APK и PWA независимы: только тесты читают общий JSON из документации.
Изменение порядка полей, разделителей или алгоритма требует пересмотра версии
контракта. Инструмент проверки полученных сообщений появится на этапе 4.
Функции `compatibilityCode` / `code` принимают только тело без строки кода;
они не являются готовым валидатором целого сообщения или подтверждением отправки.

## Входные значения

| Поле | Значение |
| --- | --- |
| `formedAtMs` | Целое число миллисекунд Unix; время формирования на устройстве |
| `utcOffsetMinutes` | Целое смещение локального времени относительно UTC, от -840 до 840; восточнее UTC — положительное |
| `variant` | `APK` или `PWA` |
| `appVersion` | Нормализованное `MAJOR.MINOR.PATCH`, без `v` и лишних ведущих нулей |
| `launchMode` | `installed` или `browser`; у APK только `installed` |
| `manufacturer`, `model` | Производитель и модель; `null`, если недоступны |
| `systemName`, `systemVersion` | Название системы и её версия; независимо определённые значения |
| `baseOs`, `baseOsVersion` | Android и его версия у Android-систем; `-` для неприменимых полей; `null` для неизвестных |
| `environmentName`, `environmentVersion` | Фактический WebView у APK или браузер у PWA |
| `storageMode` | `persistent`, `ordinary` или `null` у PWA; у APK выводится `-` |
| `archiveSource` | `demo`, `user` или `null` |
| `archiveFormat` | `7z`, `ZIP`, `ZIP64` или `null` |
| `archiveBytes` | Полный размер выбранного исходного архива в байтах, либо `null` |
| `archiveFiles` | Полное количество принятых файлов после успешного импорта, либо `null` |
| `importDurationMs` | Наблюдавшаяся длительность попытки импорта, либо `null` |
| `steps` | Состояния `launch`, `import`, `storefront`, `game` |
| `error` | Безопасная категория ошибки, только если один шаг имеет состояние `error` |

Строковые сведения отсутствуют как `null` или отсутствующее поле и выводятся
как `?`; пустые строки также дают `?`. Для целых чисел допустим общий точный
диапазон Java/JavaScript от 0 до 9 007 199 254 740 991. Java принимает `Long`
и `Integer`, без строкового преобразования или округления дробей.
Дата после учёта смещения должна попадать в годы 1970–9999.

Размеры делятся на 1024, до ТБ включительно; используется не более одного
десятичного знака с запятой, без группировки цифр. Секунды импорта выводятся
с точностью до десятых; положительная длительность менее 100 мс — `<0,1 с`.
Неизвестное время — `?`, измеренные нулевые миллисекунды — `0 с`.

## Состояния и достоверность

`success`, `not_performed`, `not_checked`, `error`, `interrupted` соответствуют
согласованным русским состояниям. У перехода в игру успешное состояние только
`recorded`, а не `success`. Если состояние не передано, оно `not_performed`.
Пропущенный предыдущий шаг не позволяет записать следующий как завершённый.
В одном снимке допускается один этап ошибки; после нового импорта сборщик
состояния обязан сбросить относящиеся к прежнему содержимому результаты.

Проверка во вкладке PWA не подтверждает установку: даже при остальных успешных
шагах итог остаётся незавершённым с предложением открыть установленное приложение.
Режим разработки `gamespaceMode=app` предназначен только для просмотра интерфейса;
сборщик отчёта различает его и реальную установку.

При неуспешном импорте число файлов всегда `?`, даже если передан счётчик
частично записанных файлов. Прерывание не объявляется ошибкой нехватки памяти
или места. Наличие файлов старого сайта не подтверждает шаги новой проверки.

Категории ошибок: `quota`, `space`, `archive`, `index`, `access`, `other`,
`demo`, `page`, `script`, `resource`, `timeout`.
Код, описание и подсказка берутся из встроенного перечня. Если категория
не передана для шага с ошибкой, используется `other`. Неизвестная категория
отклоняется; полный текст исключения, журнал и личные пути не экспортируются.
Получение демо даёт `GS-DEMO`, загрузка страницы — `GS-PAGE`, наблюдаемая ошибка
JavaScript — `GS-SCRIPT`, ресурса — `GS-RESOURCE`, ожидание свыше 30 секунд —
`GS-LOAD-TIMEOUT`. Сборщик использует существующие обработчики диагностики.
В отчёте остаётся одна ошибка на самом раннем сбойном этапе. Более поздний
успешный callback загрузки не стирает её; повторная проверка начинается явно.
Ошибку можно зафиксировать и для ранее установленного сайта, при этом его
импорт не объявляется наблюдавшимся или успешным в рамках новой проверки.
Отсутствие зарегистрированных ошибок не доказывает отсутствие всех ошибок игры:
обработчики PWA и часть обработчиков APK подключаются после загрузки документа.

## Строки, снимок и целостность

Только поля из таблицы включаются в отчёт. Для внешних строк максимум — 512
кодовых единиц UTF-16; некорректные суррогатные пары отклоняются. До формирования
снимка согласованные пробельные символы заменяются пробелами, повторы и края
убираются. Остальные управляющие C0/C1 и символы управления направлением
U+202A–U+202E, U+2066–U+2069 заменяются на U+FFFD. Значения с `;` или `"`
заключаются в кавычки; вложенные кавычки удваиваются. Двоеточия сохраняются.

После построения текста хеширование удаляет только пробельные символы из
[спецификации](./COMPATIBILITY_REPORT_RU.md#целостность-текста-gs1), сохраняя
все прочие символы. Никакой Unicode-нормализации нет; U+200B и U+FEFF не удаляются.
Полный SHA-256 считается от UTF-8, код — `GS1-` и `hex[29:35]` в верхнем регистре.
Это проверка целостности, а не подпись или доказательство прохождения испытания.

PWA строит тело синхронно до первого `await`: изменение входных данных во время
SHA-256 уже не влияет на снимок. Java возвращает готовую строку. Окно должно
хранить этот текст для просмотра, копирования и открытия формы. При каждом
открытии окна и начале новой проверки снимок автоматически формируется заново;
при ошибке формирования старый снимок не выдаётся за актуальный.

В обеих реализациях закреплена одна ссылка на Яндекс Форму. Кнопка копирует
показанный снимок и сразу открывает форму без текста в URL и промежуточной пустой
вкладки, даже при отказе или зависании копирования. Отправка через системный выбор почты или
мессенджера в отчёте совместимости не предусмотрена.

## Сохранение наблюдений

APK хранит состояние отдельно от данных игр в SharedPreferences, PWA — в
localStorage. Сбой сохранения оставляет текущие результаты в памяти и показывает
предупреждение. При изменении версии приложения, среды или принятого содержимого
нужна новая проверка; инкрементальное обновление не заменяет полную установку.
После перезапуска процесса APK незавершённая попытка отмечается как прерванная.
PWA оставляет её неподтверждённой: импорт ещё может выполняться в другой вкладке.
Причина прерывания не угадывается. Очистка браузерных данных удаляет и эти записи.

## Проверки

- PWA: `node --test test/compatibility-report.test.js` из `pwa-gamespace/`;
  также входит в обычный `npm test`.
- APK: `apk-gamespace/tests/test-diagnostics.ps1` из корня проекта.
- Эталоны покрывают успешный APK, сбой квоты PWA, неполный отчёт, вкладку,
  кавычки и Unicode, Windows, прерывание импорта и неизвестные сведения iOS.
- Отдельно проверяются явный набор пробелов, сохранение пунктуации, 40 ГБ,
  верхняя граница точных чисел, локали JVM и отбрасывание несогласованных шагов.

Эти проверки подтверждают контракт, а не получение сведений или работу
интерфейса на физических телефонах.
